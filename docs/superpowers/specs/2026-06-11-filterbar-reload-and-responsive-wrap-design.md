# FilterBar: 再読込ボタンとレスポンシブ行分け 設計

- 日付: 2026-06-11
- 対象: 画像一覧画面のフィルタバー（`src/components/FilterBar.tsx`）

## 背景・目的

画像一覧画面の上部ツールバー（`.filter-bar-slot`）に対して、2つの改善を行う。

1. **再読込ボタンの追加**: 現在のクエリで一覧を再検索する操作を、低頻度ゆえアイコン1つで提供する。
2. **狭い画面でのレスポンシブな行分け**: ウィンドウが狭いとき、ツールバーを「テキストボックス・履歴・詳細ボタン」と「それ以外」の2行に分けて、横スクロールや窮屈な詰め込みを避ける。

## 確定した要件（ブレストの回答）

- **再読込の動作**: 現在のクエリ・ソートのまま DB を再検索する（`useQueryStore.runQuery()`）。ディレクトリの再スキャンは行わない（スキャンは DirectoryPanel の既存機能）。
- **再読込ボタンの位置**: `検索` ボタンのすぐ右。アイコン1つ（`⟳` U+27F3）。
- **狭い画面のグルーピング**: 1行目＝テキストボックス＋履歴＋詳細、2行目＝それ以外。
- **折り返し方式**: 自動折り返し（内容が1行に入りきらなくなったら2行へ）。固定ブレークポイントは使わない。

## 整合性に関する重要な決定

自動折り返しは **HTML上の並び順をそのまま折り返す** ため、上下の行で要素順を入れ替えることはできない。
「詳細を1行目・検索を2行目」を自動折り返しで成立させるには、**広いとき（1行）の並び順も
「テキスト → 履歴 → 詳細 → 検索 → ⟳ → …」** にする必要がある。

→ **詳細ボタンを検索ボタンの左へ移動する**ことを確定とする（ブレスト Q2 のプレビューでは
`[検索][⟳][詳細]` だったが、グルーピング優先で `[詳細][検索][⟳]` に変更）。
ただし「**⟳ は検索のすぐ右**」という Q2 の主旨は維持する。

### レイアウト（広いとき・1行）

```
[ テキストボックス ............▾] [詳細…] │ [検索] [⟳] [スライドショー▶] 並べ替え:[v][↓] 12件 [ファイル名:表示]
        └─── グループA（入力系）───┘   └──────────── グループB（それ以外）────────────┘
```

### レイアウト（狭いとき・2行）

```
行1: [ テキストボックス ............▾] [詳細…]
行2: [検索] [⟳] [スライドショー▶] 並べ替え:[v][↓] 12件 [ファイル名:表示]
```

## 設計詳細

### 1. 再読込ボタン

- `⟳`（U+27F3）アイコン1つのボタンを `検索` ボタンのすぐ右に置く。
- クリックで `useQueryStore.runQuery()` を実行。現在の `query` / `sort` / `dir` のまま DB を再検索する。
- 失敗時は既存呼び出しに倣い `console.error("再読込に失敗しました:", e)` でログ出力（ユーザー向けトースト等は出さない）。
- アクセシビリティ: `aria-label="再読込"`、`title="再読込"`。
- スタイルは `history-btn` 同様の固定幅アイコンボタン（`.reload-btn`、`width: 32px`）。
- ローディング状態・スピンアニメーション・多重実行防止は持たない（YAGNI。`runQuery` は軽量な DB クエリ）。

### 2. レスポンシブな行分け（FilterBar 構造変更）

- `.filter-bar` を `flex-wrap: wrap` に変更し、直下の子を2つのグループ `<div>` に再編する。
  - **グループA `.fb-group-input`**: `filter-combo`（テキスト入力＋履歴 ▾）＋ `詳細…` ボタン。
    - `flex: 1 1 360px; min-width: 0;`（入力欄を可変幅にし、必要に応じて縮む）
  - **グループB `.fb-group-actions`**: `検索` ＋ `⟳`（再読込）＋ `スライドショー▶` ＋ `並べ替え`（select＋↑↓）＋ `件数` ＋ `ファイル名トグル`。
    - `flex: 1 1 auto;`
- 親 `.filter-bar` が `flex-wrap` のため、両グループが1行に収まる間は横並び、入りきらなくなると
  **グループBが丸ごと次の行へ折り返す**。折り返し幅は概ね「グループAの基準幅(360px) ＋ グループBの最小内容幅」で自動的に決まる（マジックナンバーなし）。
- 各グループは内部で `display: flex; align-items: center; gap: 8px;`。
- グリッドの `filter` 行は `grid-template-rows: auto 1fr` の `auto` なので、2行化に伴い自動的に高さが伸びる（`App.css` のグリッド定義変更は不要）。

### 3. filename-toggle の移設

- 現状 `filename-toggle` ボタンは `src/App.tsx` の `<header class="filter-bar-slot">` 内、FilterBar の兄弟要素として存在する。
- これを **FilterBar のグループB末尾へ移設**する。理由: 視覚上「それ以外」に含まれ、同一の折り返し単位（グループB）に入れないと独立して別行へ折り返してしまうため。
- FilterBar は `useQueryStore` から `showFilename` / `toggleShowFilename` を直接読んで描画する。
- `App.tsx` 側の `filename-toggle` ボタンは削除。`.filter-bar-slot` は FilterBar のみを内包する形になる。
- `.filename-toggle` の CSS（`white-space: nowrap`）はそのまま維持。

### 4. テスト

- 新規 `src/components/FilterBar.test.tsx`（既存 `FilterDialog.test.tsx` のパターンに倣う）:
  1. 再読込ボタン（`aria-label="再読込"`）が存在し、クリックで `useQueryStore.runQuery` が呼ばれる。
  2. グループ構造（`.fb-group-input` / `.fb-group-actions`）が描画される。
  3. `ファイル名` トグルが FilterBar 内に存在する。
- CSS の折り返し挙動そのものは jsdom で検証困難なため、実機（`pnpm tauri dev` 等）で手動確認する。

## 影響範囲

- 変更:
  - `src/components/FilterBar.tsx` — 再読込ボタン追加、2グループ構造化、filename-toggle 取り込み。
  - `src/App.tsx` — header から filename-toggle 削除。
  - `src/App.css` — `.filter-bar` を `flex-wrap`、`.fb-group-input` / `.fb-group-actions` / `.reload-btn` 追加。
- 新規:
  - `src/components/FilterBar.test.tsx`

## 非対象（スコープ外）

- ディレクトリの再スキャン連携（再読込はクエリ再実行のみ）。
- 再読込中のローディング表示・スピン演出・多重実行防止。
- 固定ブレークポイントによる切り替え（自動折り返しを採用）。
- ツールバー以外のUI変更。
