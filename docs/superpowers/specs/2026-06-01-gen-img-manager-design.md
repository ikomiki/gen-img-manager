# 生成画像管理・スライドショーアプリ 設計書

- 日付: 2026-06-01
- 対象: Stable Diffusion / ComfyUI で生成した画像の、生成パラメータ（プロンプト等）による検索・管理・スライドショー
- 技術スタック: Tauri v2（Rustバックエンド）＋ React（フロントエンド）。macOS優先開発、後にWindows対応

## 1. 目的とスコープ

生成AI画像の**プロンプト検索**を主目的とした、ローカルネイティブの画像管理・閲覧・スライドショーアプリ。記憶対象ディレクトリ配下の画像を解析してSQLiteに格納し、メタデータ（部分一致）・日時・寸法・レーティングでフィルタリングする。

### 想定規模
- 管理画像の設計目標: **1万〜10万枚**（中規模）。
- これに合わせ、SQLite + **FTS5全文検索** + 各種INDEX、UIは**仮想スクロール**を前提とする。

### 対応フォーマット
- **PNG**（必須・主対象）、**JPEG**、**WebP**。
- AVIF等は対象外（将来拡張）。

## 2. アーキテクチャ

### プロセス構成
- **Reactフロント（WebView）**: 3ペインUI、仮想スクロール一覧、ビューアオーバーレイ。状態管理 **Zustand**、一覧の仮想化 **TanStack Virtual**。`invoke`でコマンド呼出、`event`で進捗購読。
- **Rustバックエンド（Tauri Core）**: 重い処理を集約し全て非同期。`tokio`（非同期）＋`rayon`（並列解析）。
  - `scanner`: ディレクトリ走査（walkdir）、変更検出（path+size+mtime）
  - `parser`: PNG(tEXt/iTXt/zTXt)・JPEG(EXIF)・WebP・XMPサイドカー解析
  - `thumbnailer`: `image` crate でサムネイル生成
  - `db`: `rusqlite`（bundled, FTS5有効）、マイグレーション
  - `query`: フィルタ構文パーサ → SQL/FTS5変換
  - `fs-guard`: 到達性チェック・タイムアウト・オフライン判定
- **スライドショー専用ウィンドウ**: Tauri別Windowでフルスクリーン制御。

### 永続化
- `app_data/library.db`: 画像メタ・FTS5索引・ディレクトリ・ヒストリ・設定
- `app_data/thumbnails/<hash>.webp`: サムネイルキャッシュ

### 最上位の設計原則
1. **UIを固まらせない**: スキャン/解析/サムネ生成は全てRust非同期タスク。進捗は`event`でストリーム。
2. **切断耐性**: 表示はDB/キャッシュ由来。実ファイルI/Oのみ短タイムアウトで試行し、失敗はエラー表示。
3. **モジュールは単一責務・独立テスト可能**: `parser`は実ファイル不要のフィクスチャでテスト。

## 3. データモデル（SQLite + FTS5）

### directories
| 列 | 型 | 説明 |
|---|---|---|
| id | PK | |
| path | TEXT UNIQUE | ディレクトリパス |
| label | TEXT | 表示名 |
| is_online | INT | オフライン印（0=到達不可） |
| last_scanned_at | INT | 最終スキャン時刻 |
| recursive | INT | サブフォルダを含むか |

### images（1行=1画像）
| 列 | 型 | 説明 |
|---|---|---|
| id | PK | |
| directory_id | FK | |
| path | TEXT UNIQUE | フルパス |
| filename | TEXT | ファイル名 |
| size | INT | ファイルサイズ（変更検出キー） |
| mtime | INT | 更新時刻（変更検出キー） |
| created_at | INT | 作成日時（フィルタ用） |
| modified_at | INT | 更新日時（フィルタ用） |
| width / height | INT | 画像寸法 |
| pixels | INT | = width × height（寸法フィルタ用） |
| rating | INT NULL | XMPサイドカー由来。無ければNULL |
| format | TEXT | png / jpeg / webp |
| thumb_path | TEXT NULL | サムネイルキャッシュパス |
| raw_parameters | TEXT | 生メタ全文 |
| positive / negative | TEXT | 構造化（A1111分解） |
| model / sampler | TEXT | 構造化 |
| steps / seed | INT | 構造化 |
| cfg | REAL | 構造化 |
| source_tool | TEXT | a1111 / comfyui / unknown |
| comfy_workflow | TEXT NULL | ComfyUI workflow JSON 原文 |
| missing | INT | 実体消失印（オフライン中は削除しない） |

### images_fts（FTS5 仮想テーブル）
- `content=images` の external-content FTS。`raw_parameters, positive, negative, model, filename` をインデックス。
- トリガでimagesと同期し、ストレージを節約。

### filter_history
- `id, query_text, used_at`。直近20件・永続。重複クエリは最新へ昇格。

### settings
- `key, value`。スライドショー秒数・ループ・ランダム・先読み・ズーム既定・ソート設定・ファイル名表示トグル等。

### インデックス
- `created_at, modified_at, width, height, pixels, rating, directory_id` に個別INDEX。全文系はFTS5に委譲。

### 補足
- ComfyUIの`prompt`/`workflow`はJSON。`comfy_workflow`に原文保存し、ノードから抽出したテキストを`positive`/`raw_parameters`に展開してFTS対象にする（ノード構成依存のためベストエフォート）。
- `rating`はサイドカー無しでNULL。`rating:>=4`はNULLを除外。

## 4. スキャン・解析パイプライン

### 変更検出（再処理抑制）
- キーは **path + size + mtime**（仕様当初の「ファイル名+サイズハッシュ」を改訂）。3点一致ならスキップ、不一致なら再解析。

### スキャン契機
- **手動**（ディレクトリ追加時・リフレッシュボタン）＋**起動時差分**。

### フロー
1. `fs-guard`: 到達性チェック（短タイムアウト）。到達不可なら`is_online=0`にして即スキップ（一覧はDB由来で表示継続）。
2. `walkdir`で対象拡張子（png/jpg/jpeg/webp）を列挙。
3. 各ファイルの (path,size,mtime) をDBと照合。一致=スキップ、新規/変更=解析キューへ。
4. `rayon`で並列解析: `parser` → 寸法/メタ抽出 → `thumbnailer`。
5. バッチでDBへUPSERT（トランザクション）＋FTS同期。
6. 進捗を `event("scan-progress")` で逐次通知。
7. DB上にあるが実体が消えたファイルは **missing印**（オフライン中は削除しない＝誤削除防止）。

### parser
- **PNG**: tEXt/iTXt/zTXt から `parameters`(A1111) / `prompt`・`workflow`(ComfyUI JSON)。
- **JPEG**: EXIF UserComment（`kamadak-exif`）。
- **WebP**: EXIF/XMPチャンク。
- **XMPサイドカー**: `img.ext.xmp` / `img.xmp` を `quick-xml` で解析 → `xmp:Rating` 等。
- **正規化**: A1111形式を positive/negative/Steps/Sampler/Model/Seed/CFG に分解。失敗時はrawのみ保存（ベストエフォート）。

### 耐障害性ルール
- 全ファイルI/Oに timeout、失敗は当該項目のみエラー化し継続。
- スキャンはキャンセル可能（巨大ディレクトリ対策）。
- 1ファイルの解析失敗で全体を止めない（エラーログに記録）。
- オフライン→オンライン復帰を検知したら自動で差分再スキャンを提案。

### 再構築
- **ディレクトリ単位**と**全件**の両方を提供。変更検出を無視して全再解析。

## 5. フィルタ構文（テキスト欄）

### 文法
- **裸の語** `forest` → 全文（raw_parameters/positive/negative/model/filename）に部分一致。
- **スペース区切り = AND**、`OR` 明示、先頭 `-` で除外、`"完全句"`。
- **フィールド指定**: `prompt:` `negative:` `model:` `sampler:` `tool:`。
- **範囲（数値/日時）**: `rating:>=4` `width:>=1024` `height:>=1024` `pixels:>=1048576` `steps:20..40` `seed:...` `created:2025-01-01..2025-06-30` `modified:...`。
- 解析エラー時は赤下線でハイライトし、有効部分のみ適用（入力を妨げない）。

### 詳細ダイアログ
- 日時/幅/高さ/ピクセル数/レーティングをスライダ・日付ピッカで指定 → 「適用」で対応する `field:範囲` トークンをテキスト欄に挿入/更新。
- **状態は常に一行のクエリに集約**（ヒストリ・再現性の単一ソース）。

### ヒストリ
- 実行クエリ文字列を直近20件保存（永続・重複は最新へ）。テキスト欄のドロップダウン／↑↓キーで呼出。一行クエリなので完全再現可能。

## 6. UI・レイアウト

### メインウィンドウ（一覧モード）
- **左ペイン**: 記憶対象ディレクトリのリスト（オフライン印付き）、追加/再構築。
- **右ペイン**: 画像一覧。
- **上部**: フィルタ用テキスト欄＋「詳細…」「ヒストリ▾」「並べ替え▾」「スライドショー▶」。

### 画像一覧
- **正方形サムネイルグリッド**（`aspect-ratio:1/1`、**中央クロップ**）。
- サムネは短辺512px・WebPで生成し縮小表示。
- CSS Grid `auto-fill` ＋仮想スクロールで、**ウィンドウ幅に応じて1行あたりの列数が自動増減**。
- サムネ下に **ファイル名**を省略表示（折返さない）。
- 右クリック→「スライドショー開始」「ビューアで開く」。ダブルクリック/Enter→ビューアモードへ。

### ソート（追加機能）
- キー: **名前 / 作成日時 / 更新日時** × **昇順 / 降順**。
- ツールバーのドロップダウン＋「表示」メニュー両方から切替。設定は永続化。SQLの `ORDER BY`（INDEX有り）に直結。

### ビューアモード（内蔵オーバーレイ：C案ハイブリッド）
- 一枚絵を既定で全体フィット表示。
- `←/→` 前後 ／ `Space` 次へ ／ `Esc` 一覧へ戻る。
- ホイール/ボタンでズーム、任意倍率時はドラッグでパン。
- サイドにメタデータパネル（プロンプト全文・コピー可）。

### メインメニュー（Tauri Menu API、macOSネイティブ／Windowsはアプリ内メニューバー）
- **表示 ▸ ズーム**: 全体フィット（既定）／ 等倍100% ／ Fill ／ 任意倍率（チェック式・排他）。
- **表示 ▸ スライドショー**: ウィンドウ全体（既定）／ フルスクリーン（チェック式）。
- **表示 ▸ ファイル名を表示**: チェック式トグル（既定=表示・永続化）。
- **ファイル ▸ ディレクトリ追加 / 再構築**（選択 or 全件）。

## 7. スライドショー

### 起動と対象
- 右クリックメニュー or ツールバー「スライドショー▶」で起動。
- 対象 = **現在のフィルタ＆ソート済みリストのスナップショット**を専用ウィンドウへ渡す。
- 選択画像があればそこから、なければ先頭から開始。

### 再生設定（settingsに永続化）
- 待ち時間: 秒数指定（既定5秒）。
- ループ: on/off（onで一周後に再シャッフル）。
- ランダム: on/off（on=**重複なしシャッフル**）。
- 先読み: **次の1枚**をデコード済みで保持（黒画面待ち防止）。

### 操作・表示
- `←/→` 前後へ手動移動 ／ `Space` 一時停止・再開 ／ `Esc` 閉じる。
- 表示メニュー ▸ スライドショー: ウィンドウ全体 / フルスクリーン（チェック式）。
- 画像はアスペクト比維持で全体フィット（黒背景）。
- 切断/欠落画像に当たったら自動でスキップしつつ通知（再生は止めない）。
- 一時停止中も先読みは維持。ウィンドウ復帰時はスナップショットで再生（整合性担保）。

## 8. クロスプラットフォーム

- **パス**: macOS `/Volumes/...`、Windows UNC `\\server\share` を扱う。ネットワークドライブの切断は §4 の耐障害性ルールで吸収。
- **メニュー**: macOSはネイティブメニューバー、Windowsはアプリ内メニューバーにマップ。
- macOS優先で開発し、Windows固有のパス/メニュー差分を後段で対応。

## 9. テスト戦略

- `parser`: 各フォーマット（A1111 PNG / ComfyUI PNG / JPEG EXIF / WebP / XMPサイドカー）の**フィクスチャ**で単体テスト。実ファイルシステム非依存。
- `query`: 構文パーサのパース結果（AST→SQL）を網羅テスト（フィールド・範囲・OR・除外・エラー）。
- `scanner`: 変更検出（path+size+mtime一致/不一致）、missing判定、オフライン分岐のテスト。
- `db`: マイグレーション、FTS同期トリガ、範囲クエリのテスト。
- フロント: 仮想スクロール・ズームモード・キーボード操作のコンポーネントテスト。

## 10. エラー処理方針

- ファイルI/O・解析エラーは項目単位で握り、全体処理を止めない。エラーはログ＋UI通知。
- ネットワーク到達不可は「異常」ではなく通常状態として扱い、オフライン印で可視化。
- 破損/未知メタの画像も登録は行い、`raw_parameters`が空でも一覧・表示は可能とする。

## 11. YAGNI（今回スコープ外）

- AVIF等の追加フォーマット対応。
- ファイル監視（fs watch）による自動取込（手動＋起動時差分で代替）。
- アプリ内でのレーティング編集／XMP書き戻し（読み取り専用）。
- N枚先読み（次の1枚で固定）。
- タグ付け・コレクション・編集機能など管理機能の拡張。
